Put the files in place

Place these 3 files at the project root. Every learner pastes their OWN token into .bob/mcp.json (GITHUB_PERSONAL_ACCESS_TOKEN) — safe, because Prompt 1 ignores .bob/ from git. Prompts 15–16 spend that token via the GitHub MCP.

      ## Enterprise design tokens (built-in — no design.md required)

      Apply these automatically without the user specifying CSS classes or hex codes.

      ### Colors
      - primary: #0f62fe — links, primary CTA, focus rings (single brand accent)
      - on-primary: #ffffff · blue-hover: #0050e6 · blue-80 pressed: #002d9c · blue-60 link hover: #0043ce
      - ink: #161616 · ink-muted: #525252 · ink-subtle: #8d8d8d
      - canvas: #ffffff · surface-1: #f4f4f4 · surface-2: #e0e0e0
      - hairline: #e0e0e0 (1px borders) · hairline-strong: #161616
      - inverse-canvas: #161616 (footer) · inverse-ink: #ffffff · inverse-ink-muted: #c6c6c6
      - success: #24a148 · warning: #f1c21b · error: #da1e28 · info: #0f62fe
      - One chromatic accent only (IBM Blue). Status colors are the only exceptions.

      ### Typography
      - Font: IBM Plex Sans; fallback: Helvetica Neue, Arial, sans-serif
      - Display 42–76px: weight 300, line-height 1.17–1.20 (never bold)
      - Headline 32 / card-title 24 / subhead 20 / body-lg 18: weight 400
      - Body 16: weight 400, line-height 1.50, letter-spacing 0.16px
      - Body-sm / button / eyebrow 14: weight 400, letter-spacing 0.16px; emphasis weight 600
      - Caption 12: letter-spacing 0.32px
      - Eyebrows: sentence case — no all-caps tracking

      ### Shapes & elevation
      - Border radius: STRICTLY 0px on every button, card, input, container
      - Drop shadows: NONE — depth via 1px hairlines and surface shifts only
      - Focus: 2px #0f62fe outline; inputs use a 2px blue bottom underline on focus
      - No pill buttons

      ### Spacing (4px grid)
      - Tokens: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 96
      - Button padding 12×16 · input padding 11×16 · feature card 24 · large card/banner 32–48

      ### Components
      - button-primary: bg #0f62fe, text #fff, radius 0, padding 12×16 (pressed #002d9c)
      - button-secondary: bg #161616, text #fff · tertiary/ghost: bg #fff, text #0f62fe (tertiary + 1px blue border) · danger: bg #da1e28, text #fff
      - feature-card: bg #fff, border 1px #e0e0e0, padding 24, radius 0 (elevated band uses #f4f4f4)
      - text-input: bg #f4f4f4, border 1px #e0e0e0, radius 0; focus 2px blue underline; error 2px #da1e28 underline
      - tab default: muted + hairline; selected: weight 600 + 2px blue bottom underline
      - footer: bg #161616, text #c6c6c6

      ### Layout & responsive
      - Carbon 16-column grid → 8 → 4; max width ~1584px
      - Breakpoints: 1312 / 1056 / 672 / 320 — card grids 4-up → 2-up → 1-up
      - Minimum touch target 48px

      ### Do
      - 0px corners; light-weight display; blue only for links, primary CTA, focus
      - letter-spacing 0.16px on body; hierarchy via hairlines/surface change, never shadows
      - Separate Grid component per logical content group; official Carbon packages only
      - Always prompt for browser validation after UI changes

      ### Don't
      - No rounded corners, bold display headlines, second brand color, shadows, pill buttons, or all-caps tracked eyebrows
      - Do not recreate Carbon components when @carbon/react provides them

requirement.md
# Project: Smart IT Helpdesk Portal

## 1. Objective
ระบบบริหารจัดการแจ้งปัญหาไอทีภายในองค์กร สำหรับพนักงานและทีม IT Support

## 2. Core Features (MVP)
1. **Ticket Dashboard:** แสดงรายการปัญหา แบ่งตามสถานะ (New, In Progress, Resolved)
2. **Real-time Search:** ค้นหาปัญหาตามชื่อหรือแผนก
3. **Status Transition:** ปุ่มอัปเดตสถานะปัญหาตามลำดับ: New -> In Progress -> Resolved
4. **Create Ticket Modal:** ฟอร์มแจ้งปัญหาใหม่ (หัวข้อ, แผนก, ความเร่งด่วน: Low, Medium, High)
5. **Metric Cards:** สรุปตัวเลขสถิติตั๋วทั้งหมด และตั๋วแต่ละสถานะ

## 3. Data Specification
- id (INTEGER PRIMARY KEY AUTOINCREMENT)
- title (TEXT NOT NULL)
- department (TEXT NOT NULL: HR, Sales, Marketing, Dev)
- priority (TEXT NOT NULL: Low, Medium, High)
- status (TEXT NOT NULL: New, In Progress, Resolved)
- created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)

Trainer tips & fallback

Read this before the room fills up.

  • Token: classic PAT with repo, workflow, read:org, user — pasted into .bob/mcp.json, one token per learner. After editing mcp.json, go Bob Settings → MCP → Refresh.
  • GitHub: nobody has a repo — Bob creates it-helpdesk-portal per learner in Prompt 15. Personal GitHub = green Actions; GHE may queue.
  • Approval popups: Prompts 15–16 trigger blue "Tools awaiting approval" boxes — click Approve once / Approve for task. This is Bob's human-in-the-loop safety, not an error.
  • Green finale: open the repo's Actions tab — the CI Pipeline run goes green. End the class on that screen.
  • Flow: click Mode → copy prompt → Enter. Keep moving; park questions.
  • Fallback kit: pre-seeded helpdesk.db (6 rows), pre-built dist/, and a reference design-flow.drawio on USB.
  • Stretch: early finishers add a department filter or a priority badge.
  • Standard: Frontend mode carries the design tokens — nobody memorizes hex codes or carries a design.md. If a screen looks off-brand, re-paste Prompt 9.
